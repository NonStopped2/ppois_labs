# Консольный интерфейс интернет-магазина

```bash
./build/lab3/lab3/shop_cli --help
./build/lab3/lab3/shop_cli --demo
./build/lab3/lab3/shop_cli --script lab3/examples/purchase.input
./build/lab3/lab3/shop_cli --script - < lab3/examples/new_product.input
```

Без аргументов открывается интерактивный режим. EOF завершает ввод без зависания.
`--script` читает команды из файла, `-` означает stdin; ошибка любой команды
даёт итоговый код 1, но последующие строки продолжают исполняться. `--demo`
запускает воспроизводимый полный цикл, а не случайную генерацию. Начальные
учебные покупатели/товары доступны и в обычном режиме; цены/акции не случайны.

`--load FILE` восстанавливает магазин до запуска команд. Внутри сеанса:

```text
as operator
save "my shop.json"
load "my shop.json" replace
```

Save/load доступны оператору. `replace` — явное подтверждение полной замены.
Успешная загрузка сбрасывает выбранного покупателя и неподтверждённые previews;
ошибка сохраняет текущий магазин и previews. Автосохранения нет.

## Синтаксис и роли

Одна команда на строку. Строки с пробелами заключаются в двойные кавычки;
внутри них `\"` и `\\` задают кавычку и обратный слеш. Пустой текст — `""`.
Полнострочные комментарии начинаются с `#`. Проверяются число и тип всех
параметров; лишние параметры не игнорируются. Деньги — **целые копейки BYN**,
проценты — **basis points**, где 10000 = 100%.

`as operator` включает операторские команды, `as customer alice` — команды
конкретного покупателя. Это учебное моделирование инициатора, не настоящая
аутентификация. Покупатель не может оплатить/отменить/вернуть чужой заказ.

Начальные данные: покупатели `alice`, `bob`; адрес alice — `home`; продукт
`shirt`, SKU `SHIRT-BLUE`/`SHIRT-RED`, доставка `standard`/`express`/`pickup`,
купон `WELCOME`. Список команд с параметрами выдаёт `help` / `--help`.

## Подтверждение покупки

```text
as customer alice
cart add SHIRT-BLUE 3
order preview standard home
order place my-place
order pay order-1 3738 card yes my-pay
```

Preview показывает строки, скидку, доставку, итог и срок. Place повторно проверяет
условия и наличие товара. Если цена/права/состав изменились, требуется новый preview.
Сохранённый заказ фиксирует товарные условия; адрес можно отдельно изменить
через `order delivery-preview` → `order delivery-confirm` до оплаты.

`OPERATION_ID` выбирает вызывающая сторона. Повтор той же команды с теми же
параметрами возвращает прежний результат, а не повторяет оплату/возврат/подбор.
Один ID с другими параметрами — ошибка. Для новой операции нужен новый ID.

## Исполнение, получение, возврат

Оператор начинает подбор, учитывает все SKU, упаковывает и передаёт перевозчику.
Packed можно распаковать и исправить подбор до передачи. Покупатель подтверждает
получение через `order deliver`; только тогда учитывается товарный оборот лояльности.

`return open` принимает тройки `SKU QUANTITY REASON`. Осмотр оператора принимает
шестёрки `SKU RECEIVED ACCEPTED RESTOCK CONDITION`, где `restock ≤ accepted ≤ received`.
Получение на осмотр должно быть полным, а брак не возвращается в продаваемый остаток.
`return complete` согласует деньги, пригодный товар и лояльность, не возмещая доставку.
Невозмещённые копейки не теряются при нескольких частичных возвратах.

Примеры в `lab3/examples/` запускаются в **новом** процессе, без `--load`:

- `purchase.input` — отказ/успех оплаты, отправка, получение, частичный возврат, отчёт;
- `coupon_cancel.input` — удержание и освобождение купона при отмене;
- `new_product.input` — характеристики, два варианта, цены, приход, избранное.

Системные `clock advance SECONDS` и `clock cleanup` закрывают просроченные
неоплаченные заказы и неполученные возвраты. Оплаченный резерв по сроку оплаты
не истекает. Отчёт `report START END` использует полуинтервал и учебные часы;
подробнее — [REPORTS.md](REPORTS.md).
