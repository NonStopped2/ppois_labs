## Границы

Один магазин и склад; только физические товары; BYN в целых копейках;
один поток; учебное время; локальная моделируемая оплата. Без сайта, настоящих
карт, сети, многоскладской логистики и частичных отгрузок. Частичные возвраты есть.

## Ключевые инварианты

- Изменения каталога/адресной книги не переписывают снимки существующего заказа.
- Остаток: `0 ≤ reserved ≤ onHand`; reserve меняет reserved, dispatch уменьшает оба.
- Оплаченный резерв не истекает по сроку оплаты. Просроченный неоплаченный
  заказ закрывается вместе с резервом и удержанием купона.
- Общая сумма скидок точно распределяется по строкам; стоимость частичных
  возвратов суммарно равна исходной чистой стоимости. Никаких double для денег.
- Процент в basis points: 10000 = 100%. Доля скидки округляется вниз.
- Автоматическая скидка выбирается по минимальному общему платежу с доставкой.
  Явный купон заменяет автоматическую скидку/лояльность; скидки не складываются.
- Coupon: reserve → confirm при оплате, release только до оплаты.
  Отмена/возврат уже оплаченного заказа не восстанавливает применение купона.
- При смене доставки неоплаченного заказа товарные цены не меняются;
  новая общая сумма должна оставаться положительной.
- Отмена до отправки: освободить резерв; оплаченному вернуть всё, включая доставку.
- Возврат после получения: доставка не возвращается; пригодные единицы
  возвращаются в остаток, принятый брак — нет.
- Лояльность учитывает чистый полученный товарный оборот, а не отправку или попытку оплаты.
- Повтор operationId с теми же параметрами не повторяет эффект; с другими — ошибка.
- Системная очистка выбирает свободный ключ журнала: пользовательские operationId
  не блокируют истечение и не перезаписываются. Старые JSON-снимки остаются допустимыми.
- Команда с несколькими объектами сначала готовит изменения, затем делает
  небросающий commit. Ошибка не оставляет частично изменённый магазин,
  включая счётчик следующих ID. Выделение ID для документов и отзывов тоже подготовлено.
- Покупательские команды получают инициатора и проверяют владельца.

## Основные состояния

Заказ: AwaitingPayment → Confirmed → InFulfillment → Shipped → Delivered.
Отмена разрешена до Shipped. Возвраты не стирают историю полученного заказа.

Резерв: Held → Confirmed → Consumed; Held может стать Expired/Released,
Confirmed — Released при отмене до отправки.

Исполнение: Created → Picking → Packed → HandedOver → Delivered.
Packed можно вернуть в Picking до передачи перевозчику.

Возврат: Submitted → Inspected → Completed; до осмотра возможен Withdrawn,
мотивированный отказ — Rejected. Истёкшая неполученная заявка явно закрывается.
Одна активная заявка на заказ. Условия возврата фиксируются при покупке.

## JSON-снимки

Сохраняется полный магазин, политики, часы, счётчики, история и результаты
идемпотентных операций. Производные индексы восстанавливаются. Ссылки — ID.
Формат имеет имя и версию. Модель не зависит от JSON и файловых путей.

Загрузка: строгий разбор → временное состояние → проверка локальных и общих
инвариантов → swap. Ошибка не меняет текущий магазин. Снимок заменяет магазин,
не объединяет данные; учебное время восстанавливается, не берётся с системных часов.

Запись: уникальный временный файл рядом с назначением → проверенные write/close →
rename. При обычной ошибке прежний снимок не повреждается. Гарантия отключения
питания без реализации fsync не заявляется. Автосохранения в первой версии нет.

Обязательны тесты повреждённого JSON, неверных типов/версии/ссылок/ID/остатков;
сохранить → загрузить → продолжить оплату и частичный возврат без повторного эффекта.

## Этапы

1. Каркас, базовые значения и unit-тесты.
2. Каталог, покупатели, адресная книга и избранное.
3. Цены, акции, купоны, лояльность, точное распределение скидки.
4. Остатки, приходы, резервы и корзина.
5. Quote → checkout → оплата, истечение и отмена.
6. Подбор, упаковка, отправка и получение.
7. Осмотр и частичные возвраты с согласованием денег/остатков/лояльности.
8. Подтверждённые отзывы и воспроизводимые отчёты.
9. JSON-снимки, отдельные codec/store и CLI-команды.
10. Актуальный каталог полей/методов, независимый пересчёт поведений, покрытие,
    анализ, Doxygen, Linux/macOS CI и проверка опубликованного пакета.

CLI и документация развиваются вместе с предметными этапами. Unit-тесты
не откладываются до завершения приложения. Коммиты содержательные, с реальными датами.
