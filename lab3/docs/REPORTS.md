# Семантика отчётов

Все периоды — `[start, end)`, end не позже учебных часов магазина. Отчёт ничего
не меняет. Его контекст должен относиться к одному снимку магазина.

- **Денежный поток**: оплаты и возвраты денег по дате финансового документа
  внутри периода. Разность может быть отрицательной. Доставка выделяется отдельно;
  полная отмена возмещает её, возврат товара после получения — нет.
- **Товарная когорта**: заказы, полученные в периоде. Возвратные количества и
  товарные суммы учитываются только по событиям `ReturnCompleted` раньше end,
  не по дате открытия заявки или осмотра. Нулевой денежный возврат тоже учитывается.
- **Средний товарный чек**: чистая товарная сумма когорты / число полученных
  заказов, включая полностью возвращённые. Результат округляется вниз до копейки;
  для пустой когорты возвращается `nullopt`, не фиктивный ноль.
- **Доля возвратов**: принятые единицы / полученные единицы той же когорты.
  **Повторные покупки**: покупатели с ≥2 полученными заказами, у которых осталось
  ненулевое количество товара, / покупатели хотя бы с одним таким заказом.
  Обе доли возвращаются точной рациональной записью, без floating point.
- **ABC**: сортировка по чистой товарной выручке, ничья по SKU. Границы по умолчанию
  80% и 95%. Товар, пересекающий порог, относится к группе до пересечения.
  Нулевая выручка — C. Сравнения не переполняют произведения целых чисел.
- **Качество**: окончательные осмотры, проведённые в периоде. Отдельно показаны
  обращения, полученные единицы, принятый брак, пригодные и отклонённые единицы,
  число обращений по причинам. Это не оценка частоты уникальных дефектов.
- **RFM**: давность последнего получения относительно end, число получений в
  периоде и чистая товарная сумма до end. В отличие от повторных покупок, частота
  учитывает факт получения, даже если товар впоследствии полностью возвращён.
  Recency ≤ recent даёт 3, ≤ older — 2, иначе 1. Frequency/Monetary ≥ high дают 3,
  ≥ medium — 2, иначе 1. Без получений — `no-purchases`. Пороги задаются явно.
- **Акции**: когорта оформленных в периоде заказов, исходная скидка, факт оплаты,
  ещё действующие неоплаченные удержания купона и завершённые товарные возвраты.
  Источник — снимки и типизированная история, не только нынешний CouponBook.
  Анализ не доказывает причинный рост продаж благодаря акции.
- **Попытки оплаты**: первая попытка заказа попала в период; исход рассматривается
  до end. `PaymentBook::attemptOutcomeAnalysis` отдельно считает отказы, успехи,
  заказы, оплаченные после отказов, и способы оплаты. Повторы ID не новые попытки.

Сверка финансовых документов проводится на историческую границу end и проверяет
связи, суммы, события, оплату, отмены и возвраты. Она не приравнивает денежный поток
периода к товарной выручке когорты: это заведомо разные величины.
