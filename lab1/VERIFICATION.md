## Локально выполненные проверки

Среда: macOS arm64, Apple Clang 21, CMake 4.4.3. Проверены:

1. Полная сборка из новой папки `build/acceptance` в Release, минимальная целевая
   macOS 14.0; запуск CTest — **29/29 успешно**.
2. Catch2 v3.8.1 — **28 test cases**, в локальном прогоне **128878 assertions**.
3. CLI — **11 unittest-сценариев, 71 запуск subprocess**. Входные файлы, EOF,
   неверные значения, перезапись/отмена, сохранение состояния, ошибки исполнения.
4. Отдельная сборка `build/sanitized` с AddressSanitizer и UndefinedBehaviorSanitizer:
   все 29 CTest-проверок успешно, сообщений санитайзеров нет.
5. clang-format **18.1.8**, cppcheck и проверка Python-синтаксиса — успешно.
6. Синтаксис GitHub workflow и shell-команды проверены **actionlint** — успешно.
7. Doxygen: `cmake --build build/acceptance --target docs` — HTML сгенерирован,
   предупреждений нет. Исходная конфигурация включает WARN_AS_ERROR.
8. `tools/package.py`: установка в отдельный staging-каталог, smoke-тесты и
   создание `build/acceptance/packages/ppois-lab1-macos-arm64.tar.gz`.
   Оба приложения отдельно запущены после распаковки архива. Зависимости бинарников
   проверены `otool`: только системные libc++ и libSystem, не CMake/IDE/Homebrew.

### Независимые модели

- Повороты кубика проверяются через трёхмерные координаты и нормали всех наклеек,
  с поворотом на -90 градусов, без использования таблицы соседей реализации.
  Проверены все грани на 8 предварительно перемешанных состояниях.
- Машина сравнивается пошагово с отдельным интерпретатором на сырых правилах,
  std::set и координате, без вызова PostMachine::step или действий Tape:
  1000 воспроизводимо сгенерированных программ, до 64 шагов на программу.
- Дополнительно проверено увеличение унарных блоков длины 0..20, обе ветви IF,
  ошибки, остановка, отрицательные координаты и переполнение.

Эти проверки повышают уверенность в реализации, но не доказывают корректность
для всех возможных программ и не заменяют понимание кода на защите.

## Реальное покрытие строк LLVM

Профили собраны заново для каждого режима, без смешивания со старыми прогонами.
Catch2, тестовый код и стандартная библиотека исключены. Нет исключения отдельных
производственных функций ради процента.

| Область | Кубик | Машина Поста | Всего |
|---|---:|---:|---:|
| Только unit-тесты: src/ и исполняемые строки include/ | 143/143 = 100% | 342/342 = 100% | 485/485 = 100% |
| Unit + CLI: также весь app/ | 400/403 = 99,26% | 645/648 = 99,54% | 1045/1051 = 99,43% |

Скрипт проверяет **строго больше 90%** отдельно по каждому варианту и суммарно.
Проверена и граница самого gate на синтетических данных: ровно 90% отклоняется,
91% принимается. HTML и JSON находятся в:

- `build/coverage/coverage/` — весь производственный код;
- `build/coverage/unit-coverage/` — только классы и только Catch2.

Проценты относятся к строкам, не являются обещанием 100% покрытия ветвей.
При изменении кода отчёты необходимо пересоздать.

## Ограничения, явно отражённые в документации

- Кубик: загрузка не проверяет все физические ограничения ориентаций/перестановок.
- Машина: теоретическая бесконечная лента моделируется координатами int64_t;
  выход за диапазон отклоняется без переполнения.
- Начальная команда — наименьший положительный номер, либо восстановленный CURRENT.
- Отсутствующие переходы разрешены при редактировании; проверяется выбранный переход.
- Лимит выполнения — защита приложения, а не команда HALT; прогресс не откатывается.
- Потоковые операторы не проверяют конец всего файла, CLI проверяет.
- Ошибочный формат не заменяет объект, но позиция потока не откатывается.
