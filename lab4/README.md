# Лабораторная работа №4 · обобщённое программирование

Вариант №2. Первая часть — Cocktail sort и Strand sort. Вторая — ориентированный
граф на матрице смежности (вариант 2.1.2).
[Условие преподавателя](https://github.com/alix-zzh/ppois-course/blob/master/ru/lab4.md)

## Сборка и демонстрация

Из корня репозитория, с CMake ≥3.20 и компилятором C++20:

```bash
cmake -S . -B build/lab4 -DBUILD_LAB4=ON -DBUILD_LAB1=OFF -DBUILD_LAB2=OFF -DBUILD_LAB3=OFF
cmake --build build/lab4 --parallel 4
ctest --test-dir build/lab4 -L '^lab4-' --no-tests=error --output-on-failure
./build/lab4/lab4/lab4_cli
./build/lab4/lab4/lab4_cli < lab4/examples/demo.input
```

Для общей сборки всех четырёх работ достаточно указать `-DBUILD_LAB4=ON`
в новом каталоге сборки. Изолированная сборка с `-DBUILD_TESTING=OFF`
собирает CLI без загрузки Catch2. При первой сборке тестов CMake скачивает
Catch2 3.8.1 и проверяет SHA-256.

В меню `help` перечисляет команды. `sort cocktail 4 -2 0 4` сортирует
числа, `tasks strand` показывает устойчивую сортировку массива задач
по приоритету. `demo` заполняет пустой граф. После неё `degree 2`
показывает полустепени вершины, `arc-degree 1 2` — степень дуги,
а `walk incident 2 reverse` — обратный обход её инцидентных дуг.
Команда `show` выводит значения с ID и все дуги. Граф живёт в памяти до
завершения программы.

## Сортировки

`cocktailSort(first, last, compare)` и `strandSort(first, last, compare)`
изменяют полуинтервал `[first, last)`. Сравнение по умолчанию — `std::less<>`.
Компаратор задаёт строгий слабый порядок. Cocktail требует двунаправленный
итератор, Strand — прямой. Обе сортировки требуют возможность обменять элементы
через итераторы.
Оба интерфейса поддерживают обычный массив и `std::vector`, включая элементы
пользовательского типа, удовлетворяющие этому контракту.

| Алгоритм | Как работает | Время | Дополнительная память |
| --- | --- | --- | --- |
| Cocktail | Проход вправо ставит последний по порядку элемент на правую границу, проход влево — первый на левую. Проход без обменов завершает сортировку. | `O(n²)` в худшем случае, `O(n)` на упорядоченном входе | `O(1)` |
| Strand | Выделяет и сливает упорядоченные подпоследовательности позиций. Затем переставляет элементы по рассчитанному порядку. | `O(n²)` в худшем случае, `O(n)`, когда весь вход образует одну подпоследовательность | `O(n)` |

Обе сортировки устойчивы. Cocktail обменивает только соседей, которые стоят
в обратном порядке. Strand включает эквивалентные элементы в одну
подпоследовательность, когда доходит до них с тем же допустимым последним ключом.
При слиянии приоритет получают эквивалентные элементы из уже накопленного списка.
В примере `Write tests` и `Review docs` имеют одинаковый приоритет и сохраняют
взаимный порядок.

Strand завершает сравнения и выделяет память для перестановки до первого
обмена элементов. Если на этом этапе выброшено исключение, исходный диапазон
сохраняет порядок и значения. Если исключение выбрасывает сам обмен, результат
зависит от его контракта и от уже выполненных перестановок.

## Контракт DirectedGraph

`DirectedGraph<T>` хранит копируемые значения. `addVertex` возвращает
ID в пределах графа. Значение доступно через `value(id)`, несколько вершин
могут содержать одинаковые значения. Добавление и удаление других вершин
сохраняет ID оставшихся. Копирование сохраняет ID, значения и дуги и даёт
независимые контейнеры. При копирующем присваивании значения и ID берутся из
присваиваемого графа. Сравнения используют последовательность значений и
направленные связи в её порядке. Для сравнений значения должны поддерживать
соответствующие операции с согласованными равенством и строгим слабым порядком.

`containsVertex` и `containsEdge` отвечают на проверку наличия. Обращение
к неизвестной вершине вызывает `std::out_of_range`. Петля, дубликат дуги,
удаление отсутствующей дуги и запрос её степени вызывают `std::invalid_argument`.
Удаление вершины убирает все её входящие и выходящие дуги. Перестройка
матрицы и копирование значений завершаются до обновления графа.

Степень вершины равна сумме входящей и исходящей полустепеней. Степень дуги
по принятому в этой работе определению — число других дуг с любым общим концом.
Например, при `A → B`, `B → A` и `B → C` степень `A → B` равна 2.
В сумме степеней концов исходная дуга учитывается дважды, а обратная дуга,
если она существует, — на один раз больше нужного.

### Обход и сложность

| Диапазон | Что выдаёт | Полный обход |
| --- | --- | --- |
| `vertices()`, `begin()/end()` | Значения в порядке добавления | `O(V)` |
| `edges()` | Пары ID `(откуда, куда)` в порядке строк матрицы | `O(V²)` |
| `incidentEdges(id)` | Входящие дуги, затем исходящие | `O(V)` |
| `adjacentVertices(id)` | Значения вершин, в которые ведут исходящие дуги из указанной вершины | `O(V)` |

У константного графа диапазоны используют константные итераторы. Для каждого
диапазона `std::views::reverse` строит обратный обход. Обычный итератор по
вершинам допускает редактирование значения. Пара ID дуги выдаётся как значение.
`removeVertex` и `removeEdge` принимают итераторы соответствующих общих диапазонов.
Операции отклоняют чужой итератор, `end()` и итератор, инвалидированный изменением
графа. Любое успешное изменение состава вершин или дуг, `clear` и присваивание
другого графа инвалидируют итераторы. Изменение только значения через ссылку
сохраняет их. Вывод `operator<<` обходит вершины и дуги через `std::for_each`.

Матрица содержит `V²` ячеек. Поиск ID и вычисление степеней занимают `O(V)`,
поэтому публичные операции над одной дугой по ID тоже `O(V)`. Обновление
ячейки после поиска концов занимает `O(1)`. Добавление или удаление вершины
перестраивает матрицу за `O(V²)`. Счётчики вершин и дуг доступны за `O(1)`.

## Проверки и релиз

```bash
cmake -S . -B build/lab4-coverage -DBUILD_LAB4=ON -DBUILD_LAB1=OFF -DBUILD_LAB2=OFF \
  -DBUILD_LAB3=OFF -DCMAKE_BUILD_TYPE=Debug -DLAB4_ENABLE_COVERAGE=ON
cmake --build build/lab4-coverage --parallel 4
python3 lab4/tools/coverage.py --build-dir build/lab4-coverage
python3 lab4/tools/coverage.py --build-dir build/lab4-coverage --with-ui
python3 lab4/tools/quality.py
cmake --build build/lab4-coverage --target lab4_docs
```

Покрытие измеряется LLVM по исполняемым строкам. Первый режим запускает
Catch2-тесты сортировок и графа. Второй включает тесты консольного слоя.
Оба режима требуют результат строго выше 90%. Точка входа `main.cpp`
проверяется запуском собранного и распакованного приложения. Для санитайзеров
следует настроить отдельную Debug-сборку с `LAB4_ENABLE_SANITIZERS=ON`.
Проверка качества использует clang-format 18.1.8, cppcheck и проверку
самостоятельной компиляции заголовков. Цель `lab4_docs` появляется при
установленном Doxygen.

Workflow [lab4.yml](../.github/workflows/lab4.yml) запускает проверки на
Linux и macOS. Установка компонента `lab4` включает CLI, это руководство
и демонстрацию. Пакет из отдельной сборки Release проверяется после переноса,
архивирования и распаковки. На macOS сборка CI задаёт минимальную версию 14.0.
Для запуска скачанного пакета нужны соответствующие ОС и архитектура.

```bash
./bin/lab4_cli < share/ppois_lab4/examples/demo.input
```

Согласованный тег `lab4-vX.Y.Z` выпускает предварительный релиз. Push в
`main` после одобренного PR выпускает `lab4-main-<SHA>` для изменений lab4
или общей инфраструктуры. Архивы и их SHA-256 публикуются в
[Releases](https://github.com/NonStopped2/ppois_labs/releases). После публикации
CI скачивает пакеты из Releases и проверяет распакованные Linux- и macOS-приложения.
